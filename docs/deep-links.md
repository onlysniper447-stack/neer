# Checker deep links

This is the local Phase 5 contract, pending preview browser acceptance, not a production deployment announcement. See [API](api.md), [limits](limits.md), [versioning](versioning.md) and [finding messages](findings.md).

## Two distinct entry modes

- `/check` without parameters preserves the existing manual starting page.
- Exactly `address`, optionally with `memo`, preserves the established **legacy quote lookup** and subsequent manual sending-details form. It is not an incomplete automatic verification and does not auto-run a completed personal-send check. Existing pasted-address/memo validation still applies.
- Any new verification-context parameter selects automatic verification. The complete address/network/token/amount input must pass the **same canonical shared validator** used by the API. Partial or invalid verification links show an editable form/error, with no quote lookup or verification call. Duplicate or unknown query parameters are rejected in either mode. `quoteId` is deferred and always rejected, never ignored.

Existing manual links generated by PasteForm, tracker and retry controls use only address/memo; no other established parameters were found.

## Accepted parameters

All parameters are single-valued and case-sensitive. Root/nested arbitrary JSON objects, raw quotes, transaction drafts, keys, rules and tracking parameters are not accepted.

| Query name | API mapping | Meaning |
|---|---|---|
| `address` | `depositAddress` | Required pasted deposit address. No `depositAddress` query alias. |
| `network` | `network` | Required canonical selected sending network ID for automatic verification, such as eth. |
| `token` | `token` | Required canonical catalog assetId for automatic verification, not symbol/contract shorthand. |
| `amount` | `amount` | Required human-readable decimal amount for automatic verification, not base units. Metadata supplies decimals; precision is not guessed. |
| `memo` | `memo` | Optional declared send memo. Empty query value means explicit null/no send memo; omission inherits lookup context. Legacy lookup treats this as its lookup memo under the existing schema. |
| `lookupMemo` | `lookupMemo` | Optional separate quote lookup memo. Empty means null; omission defaults to memo or null. This selects automatic-verification mode, even without other context. |
| `recipient` | `expectedRecipient` | Optional (since 1.1.0) receiving address the user expects funds at. Without it an otherwise matching link shows Check this, never Checks passed. |
| `recipientNetwork` | `expectedDestinationChain` | Optional (since 1.1.0) canonical network ID where the user expects to receive. |
| `source` | `source` | Optional wallet/exchange/unknown. Omission stays unknown and warns, never an assumed wallet/pass. |
| `chainId` | `transfer.chainId` | Optional digits-only positive safe-integer EVM chain ID; zero, decimal/exponent/negative/unsafe values reject. |
| `from` | `transfer.from` | Optional declared sender, not proof of control. |
| `to` | `transfer.to` | Optional declared destination for comparison with the quote. |

Shared length/format/decimal validation remains authoritative. Empty from/to/chainId are invalid when explicitly supplied. URL encoding must preserve literal characters; use URLSearchParams, including for `+` in memos. No `transfer` JSON query field, source inference, arbitrary passthrough or quoteId lookup is added.

## Automatic check and editing

A valid complete link runs **on the server while /check loads**, using the same quote/token adapter and canonical amount conversion as the API. It is not a hidden browser POST to a second endpoint. The entire existing legacy result is kept for the shared result renderer, including checks, severity, actions, freshness, signed quote and receipt; the public API's smaller projection is unchanged.

The result appears as a manual check would, with existing stale/expired safe-result protection. Change details hides that result and opens the prefilled form. Form submission validates the same contract before a native GET navigation, so rerunning unchanged details requests a fresh server check instead of replaying client router state. Invalid edits do not run. Rate limits and unavailable/unknown findings cannot become a pass. Server metadata-dependent precision errors show the form without a stale result.

## Copy link, memo and receiving-address consent

The result panel's Copy link control starts with **Include memo in link unchecked**. By default **both memo and lookupMemo are omitted**, including a standalone lookupMemo. Explicit opt-in includes each defined memo, preserving an empty/null value. Consent is remounted/reset for a different input/result or when leaving the result to edit. It is not saved in storage.

The receiving address follows the same pattern with its own **Include receiving address in link** checkbox, shown only when the check had one, and unchecked by default. By default **both `recipient` and `recipientNetwork` are omitted**. A receiving address is less sensitive than a memo, but it can identify the user's wallet, and whoever opens a shared link should enter their own receiving address anyway, so it is opt-in rather than copied silently.

A copied complete link includes canonical network/token/human amount/source and any declared transfer context. A legacy result without complete sending context copies only its legacy address lookup, not a fabricated automatic verification. Missing lookup memo can prevent the provider finding a quote; the recipient must supply it privately if needed. Copying does not extend a quote deadline or preserve a pass forever.

## Fake example

This address/token/memos are **synthetic**, not a real quote. Never send funds to them. A public preview can honestly return not-found/unavailable for this example; it must not install a public fixture backdoor to make it pass.

```text
/check?address=FAKE_DEPOSIT_ADDRESS&network=eth&token=nep141%3Afake-usdc.omft.near&amount=5&memo=FAKE_SEND&lookupMemo=FAKE_LOOKUP&source=unknown&chainId=1&from=FAKE_FROM&to=FAKE_TO
```

No quoteId is shown because it is unsupported. A missing source produces an unknown-source warning when the quote is available; no quote or unknown required check can authorize sending.

## Privacy and evidence limits

The new parser/automatic-check/editor/copy path writes no query values to localStorage, sessionStorage, application analytics or application logs. It does not call the existing local-stats recorder. Existing unrelated manual verdict/network counts and theme behavior are unchanged. Copying to the clipboard is an explicit user action, not background persistence.

**URLs are not private storage.** Browser history, copied/shared links, hosting/framework/proxy logs and provider lookups can retain addresses/memos and other details. GET form submissions also put values in the URL. These infrastructure/browser behaviors are not controlled by the application and are not a no-storage guarantee. The API/provider still receives the lookup address/memo. See [limits](limits.md) and the [privacy source](../apps/web/app/%28product%29/privacy/page.tsx).

No wallet connection, signing or transfer is added. A result does not verify counterparty/address ownership, guarantee delivery or recover sent funds. Current unit/SSR checks do not substitute for the pending preview browser gate or a real-transfer test; no real funds should be used for acceptance.
